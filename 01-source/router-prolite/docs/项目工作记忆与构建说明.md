### 2.1 五项稳定性修复（2026-11-19 下午）

问题与改法均为“实际复现后修”：

1. **主面板磁贴**：原逻辑固定截断为 4 个且能力磁贴优先，核心磁贴被挤掉。改为按设备能力生成并保证核心磁贴可见；相关文件 `tiles.go`、`tiles_test.go`、`frontend/app.js`。
2. **延迟探测**：原固定 ping `1.1.1.1`，国内网络易丢包导致延迟长期异常。改为目标顺序 `223.5.5.5` → `1.1.1.1` → WAN 网关，首个成功即停止；命令做 shell 引号防护；5 秒一轮、单次 6 秒超时。相关文件 `telemetry.go`、`router.go`、`telemetry_test.go`。
3. **内存误报**：旧固件 ubus 只返回 total/free 时，原算法把已用内存算成 100%。改为 `MemAvailable` 优先，缺失时回退 `MemFree`，再回退 `/proc/meminfo`。相关文件 `telemetry.go`、`telemetry_test.go`。
4. **轮询压力**：前端固定高频轮询会持续占用路由器 SSH/shell。改为正常 900ms、窗口隐藏 4s、失败指数退避（1.7 倍，上限 6s）、上一轮未完成不叠加请求。相关文件 `frontend/app.js`。
5. **无线停用**：原逻辑把单个 SSID 的 `disabled` 写到 `wifi-device`，导致同射频所有 SSID 一起掉线。改为只写对应 `wifi-iface`，仅当射频下没有启用的 SSID 时才停用射频；新增 `radioShouldDisable` 测试。相关文件 `settings.go`、`settings_test.go`。

当轮完成 `go vet`、`go test`、构建与 mock 回归，未做真机写入。

### 2.3 真机失败码与对应修复（2026-11-19 18:45 前后）

一次真机预演连续失败，定位到四个根因并修复：

| 现象/错误码 | 根因 | 修复 |
| --- | --- | --- |
| 无可用包源（`IDX_UNREACHABLE` 一类） | 只读 `/etc/apk/repositories`，漏掉新版 apk 的 `/etc/apk/repositories.d/*.list` | 两处都读，并支持多行、`$arch` 替换、显式索引地址 |
| 架构不匹配（`ARCH_MISMATCH` / `ARCH_UNKNOWN`） | 架构判定未优先使用 `/etc/apk/arch` | 优先 `/etc/apk/arch`，其次 `apk --print-arch`，再回退 opkg |
| `FORMAT_UNSUPPORTED` | 不认识 apk v3 的 `packages.adb`（ADBd）与 `.apk` 结构 | 新增 `adbindex.go`：识别 ADBd、DEFLATE 解压、解析 indx 块、按包内 ADB payload SHA256 校验；探测顺序 `packages.adb` → `APKINDEX.tar.gz` → `Packages.gz` |
| 依赖缺失（`DEP_UNRESOLVED`） | 依赖链含 kmod，市场侧无法保证内核 ABI 匹配 | 明确提示“市场不提供 kmod 安装入口”，引导设备侧解析；ABI 不匹配直接失败 |

修复后用纯 noarch 的 `luci-app-uhttpd` 完成真机安装、回读、卸载回滚；未使用 `--force`，未触碰 kmod/内核包。

## 3. 关键决策与硬约束

1. **内核相关包不走本机闭包**：kmod、kernel、kernel-*、linux-*、直接依赖 kernel 的包，本机闭包模式直接拒绝；只能用设备侧解析，由设备按内核哈希选择 kmod。
2. **不使用 `--force`**；真实安装与回滚都不使用。`--allow-untrusted` 的现状见第 7 节“已知偏差”：代码保留了一个仅对 UNTRUSTED 单包、且桌面端已校验 SHA256 的重试分支，本次未触发，但与“不使用 --allow-untrusted”的硬约束存在冲突，尚未移除。
3. **真实写入三重门**：`%AppData%\ProLite\device-write-allow.json` 必须存在且 `host` 与当前设备一致、`allowOverlay=true`、`allowTmp=true`；确认框逐字输入当前设备地址；勾选“我确认写入设备”与“确认写入 overlay 与 /tmp”。危险包还需 `allowDangerous=true` 且界面额外勾选。
4. **写前快照、装后回读**：安装前记录已装包及版本、`/etc/init.d` 列表、`/etc/config/*` 的 SHA256；安装后再次采集并 diff，输出新增包、新增 init.d、变更配置。不重启任何服务。
5. **文件只写 `/tmp/prolite-<jobID>/`**，任务结束清理；不改设备 feed 配置，不执行 `apk update` / `opkg update`（设备侧预演在缺索引时会做一次 `apk update`，属于设备自身解析路径，需在界面说明中体现）。
6. **系统盘禁止挂载/卸载**：`/`、`/overlay`、`/rom`、`/boot*`、系统运行盘整盘、EFI 分区都标记 `protected`，`MountStorage` / `UnmountStorage` 直接拒绝；挂载点只允许 `/mnt/<简单名称>`，非空目录拒绝，挂载后回读 `/proc/mounts`。
7. **控制中心只有一个入口**：顶栏蓝色按钮（Ctrl+K 同效）；不恢复设备卡/插件卡链接或底部横条。
8. **市场只保留全量列表**：无“精选”入口、文案与 mock 数据；每页 10 个，卡片含已安装状态、版本、体积、分类、中文说明、风险标。
9. **翻译离线**：本地静态缓存，不联网调用翻译 API、不引入密钥服务；键为“包名@版本”；未命中显示英文并标“待翻译”，不显示空、不伪造。
10. **标签永远显示文字**：任何宽度都不图标化、不用 tooltip 代替；520 只允许缩小字号、收紧内边距、调整留白。
11. **窗口圆角要么完整、要么系统方角**：Win11 用 DWM；兜底区域裁剪；最大化移除区域；Win10 不做半截 CSS 圆角。
12. **Git 历史不改写**：只追加提交，不 force；推送前核对文件大小与哈希。

## 4. 实操流程

### 4.1 连接设备

1. 启动 `ProLite.exe`，主机默认 `192.168.100.1`，端口 `22`，用户 `root`。
2. 选择认证方式：
   - **免密（none）**：设备允许空认证时使用；当前 MelonPi M21 即此状态。
   - **密码**：设备设置了 root 密码时使用（现场示例 `admin`，以设备实际为准）；密码只在本次会话内存中使用，不写盘、不进日志。
   - **私钥**：文件选择器指定私钥，可填 passphrase；只保存路径，不保存私钥内容。
   - 另支持 SSH Agent。
3. 首次连接展示主机密钥 SHA256 指纹，确认后 TOFU 固定；指纹变化拒绝连接，可在连接页重置。
4. 连接成功后 `Router.input` 保存会话凭据；后续安装、存储、控制台、SFTP 都通过 `ensureClient()` 复用，断线自动重建；认证失败标记 `credExpired` 并提示重新输入；断开设备清空内存凭据。

### 4.2 预演

- **设备侧预演（默认）**：`apk add --simulate <包名>`；若设备没有索引缓存报 `opening from cache` 一类错误，先执行一次 `apk update` 再重试同一条 simulate。opkg 设备用 `opkg install --noaction`。不下载、不安装、不写包数据库。
- **本机闭包预演**：PC 解析完整依赖树，界面展示依赖列表与总体积；下载、校验后上传到 `/tmp/prolite-<jobID>/pkgs/`，再执行 `apk --repositories-file /dev/null add --simulate <files>`（旧版 apk 回退 `--no-network`）。kmod/内核相关包在下载前就被拒绝。
- 两条路径都会做架构、内核 ABI、overlay/tmp 空间、冲突/替换预检；任一 `fail` 停止，不进入上传或安装。

### 4.3 真实安装

1. 预演必须通过。
2. 确认授权文件存在且匹配当前 host；确认框逐字输入设备地址；勾选两项确认；危险包额外勾选。
3. 后端要求 `commit=true`、`confirmed=true`、`confirmWrites=true`、`confirmText=host`；否则拒绝（`WRITE_NOT_AUTHORIZED` 等）。
4. 写前快照（包、init.d、配置哈希）。
5. 设备侧模式执行 `apk --repositories-file /dev/null add <包>` 或设备自己下载安装；本机闭包模式逐个安装已上传的本地包。
6. 装后回读并 diff；结果包含新增包、新增 init.d、变更配置；不重启服务。
7. 日志：`%AppData%\ProLite\logs\install-<jobID>.log`，任务快照里有日志路径。

真机证据：2026-11-19 用 `luci-app-uhttpd` 完成安装/回读/卸载；2026-11-20 用设备侧模式安装 `luci-app-ddns` 并卸载回滚，包数量回到安装前。回滚命令为 `apk del <本次新增包>`，不使用 `--force` / `--allow-untrusted`。

### 4.4 回滚

- 应用**不自动卸载**：任务结果标记 `Rollbackable`，并给出 `Changes.PackagesAdded`；取消任务时也只停止后续包，不自动卸载已完成项。
